# ExamHub Web

Веб-версия школьного проекта: HTML, CSS, JavaScript и небольшой WSGI-сервер Python. Локальный сервер работает без сторонних пакетов. Gunicorn нужен для хостинга, psycopg — для PostgreSQL.

## Быстрый запуск на компьютере

Открой терминал в папке web и выполни:

```powershell
python app.py
```

Открой http://127.0.0.1:8000 в браузере. Остановка — Ctrl+C. Файл index.html отдельно не запускает приложение: нужен сервер.

Учебный режим работает без ключей. В нём 12 математических задач исходного проекта и 27 демонстрационных примеров по другим экзаменационным предметам. ОГЭ — 9 класс, ЕГЭ — 11 класс. Для других классов создай задания через Gemini. Набор демонстрационный, это не полный банк экзамена.

## DeepSeek вместо Gemini

Поддерживаются оба сервиса. Для DeepSeek создай API-ключ в кабинете https://platform.deepseek.com/. Доступ к API и баланс проверяются отдельно от бесплатного чата. Бесплатная квота не гарантируется; приложение показывает отдельную ошибку при недостаточном балансе.

В терминале PowerShell останови сервер через Ctrl+C и выполни:

```powershell
$env:AI_PROVIDER="deepseek"
$env:DEEPSEEK_API_KEY="твой_ключ"
$env:DEEPSEEK_MODEL="deepseek-chat"
python app.py
```

Ключ не отправляй в чат и не загружай в GitHub. .env.example — образец, а не автоматически загружаемый файл. Без AI_PROVIDER приложение выбирает DeepSeek, если указан DEEPSEEK_API_KEY; иначе Gemini. Явная AI_PROVIDER имеет приоритет. Для возврата к Gemini задай AI_PROVIDER="gemini" и GEMINI_API_KEY.

Обнови страницу через Ctrl+F5. Заголовок генератора покажет выбранный сервис. Сервер создаёт пять заданий и шпаргалку; ошибки ключа, баланса, лимитов и некорректного JSON обрабатываются отдельно. Код DeepSeek находится в gemini.py вместе с общей проверкой результатов — имя файла сохранено для совместимости.

На Render задай AI_PROVIDER=deepseek, DEEPSEEK_API_KEY, DEEPSEEK_MODEL=deepseek-chat и прежние DATABASE_URL и SECRET_KEY. Текущий render.yaml настроен на DeepSeek. GEMINI_API_KEY для этого не нужен. После изменения переменных перезапусти сервис. Доступность модели проверяется живым запросом с твоим ключом; локальные тесты не расходуют API-баланс.

## Подключение Gemini локально (альтернатива)

Создай ключ в Google AI Studio в своём аккаунте. Доступность Gemini, модели и бесплатная квота зависят от аккаунта и региона. В том же терминале PowerShell перед запуском задай:

```powershell
$env:AI_PROVIDER="gemini"
$env:GEMINI_API_KEY="твой_ключ"
$env:GEMINI_MODEL="gemini-2.5-flash"
python app.py
```

Это переменные окружения, ключ не нужно вставлять в Python или JavaScript. Файл .env.example — только образец: приложение не загружает .env автоматически. Ключ не отправляй в чат и не загружай в GitHub.

В тренировке выбери экзамен, класс, предмет, тему и уровень, затем нажми «Создать 5 заданий». Сохраняются задания, допустимые ответы, подсказки, решения и самостоятельная шпаргалка по теме. Автоматически откроется только новый набор. «Открыть задания» показывает все сохранённые задания выбранного класса и предмета.

Для ЕГЭ по математике доступны уровни «Базовая» и «Профильная». Это указание генератору; сайт не воспроизводит полный официальный вариант экзамена. Для языков и литературы реализованы краткие ответы, без проверки сочинений, аудирования или устной речи.

Если указанная модель недоступна аккаунту, укажи доступную модель Gemini в GEMINI_MODEL. Генерация ограничена десятью наборами в час на профиль, с паузой 20 секунд. Ошибочный ответ API не сохраняется как набор задач. Реальное подключение требует твоего ключа; автоматические проверки используют имитацию ответа API.

## Данные и поведение

Будущие номера блокируются и в браузере, и на сервере. Следующий номер открывается после отправки любого непустого ответа, в том числе ошибочного — как в настольной версии. К открытым заданиям можно возвращаться. Ошибка показывает подсказку, верный ответ — разбор. Повтор ошибок берёт задания с последней неправильной попыткой; после исправления они исчезают из повторения.

Статистика строится отдельно для ОГЭ и ЕГЭ по выбранному предмету и классу. Процент считается от всех попыток, ошибки до подсказки учитываются. Шпаргалки ищутся по теме и тексту; полное описание отображается отдельно и прокручивается.

Локально данные хранятся в instance/web.sqlite. Это отдельная база, настольная exam.db не изменяется. Исходные задания и теория перенесены в seed.json. Старые личные ответы из настольной базы автоматически не импортируются.

Профиль анонимный, привязан к подписанной HttpOnly-cookie. Прогресс хранится на сервере, cookie содержит только идентификатор и подпись. У разных браузеров разные истории. Очистка cookie лишает доступа к этому профилю; восстановления по паролю и синхронизации между устройствами пока нет. Смена SECRET_KEY также сбрасывает доступ, поэтому на хостинге сохраняй его постоянным. Незаконченный последний тест восстанавливается после перезагрузки страницы.

## Публикация на Render

Для постоянных данных нужна внешняя PostgreSQL, например проект Supabase. На бесплатном веб-сервисе Render не следует хранить рабочую SQLite: локальные файлы могут исчезать при перезапуске или развёртывании. Условия бесплатных планов и доступность регистрации проверь в своих аккаунтах; сайт не требует платных функций по коду. Бесплатный сервер может засыпать без посетителей.

Создай пустой репозиторий GitHub и загрузи содержимое папки web в корень репозитория. Не загружай instance, ключи, .env и __pycache__. Файл .gitignore уже подготовлен. В репозитории должны находиться app.py, logic.py, gemini.py, catalog.py, seed.json, templates, static, requirements.txt и render.yaml.

В Supabase создай проект. В Connect найди PostgreSQL connection string для Session pooler (обычно порт 5432). Этот вариант полезен при отсутствии IPv6. Подставь пароль базы; специальные символы пароля должны быть URL-кодированы. Используй выданную сервисом строку и SSL (sslmode=require). Нужна именно строка подключения PostgreSQL, не публичный anon-key и не адрес REST API.

В Render подключи GitHub и создай New → Web Service. Выбери репозиторий. Если в GitHub загружена целиком папка ExamHub, установи Root Directory: web; если содержимое web находится в корне репозитория, оставь Root Directory пустым.

Параметры сервиса:

```text
Runtime: Python
Build Command: pip install -r requirements.txt
Start Command: gunicorn app:application --bind 0.0.0.0:$PORT --workers 2 --threads 2 --timeout 90
Health Check Path: /health
Instance Type: Free (если доступен аккаунту)
```

В Environment добавь AI_PROVIDER=deepseek, DEEPSEEK_API_KEY, DEEPSEEK_MODEL, DATABASE_URL и SECRET_KEY (или Gemini-переменные для Gemini). SECRET_KEY — длинная случайная строка; её можно сгенерировать локально:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

В DATABASE_URL вставь строку подключения Supabase. Для опубликованного сайта обязательны SECRET_KEY и DATABASE_URL; без них приложение намеренно не стартует. Можно сначала развернуть без API-ключа выбранного ИИ и проверить учебный режим.

Альтернатива ручным полям — Render Blueprint из render.yaml. Он создаст SECRET_KEY и попросит ввести внешние ключи. Файл предполагает, что содержимое web находится в корне репозитория.

После Deploy открой адрес Render, создай тренировку, отправь ответ и перезагрузи страницу. Проверь сохранение даты и статистики, затем генерацию Gemini. Публикация в аккаунте Render и живой запрос Gemini не выполняются одним только созданием этих файлов.

## Проверка

```powershell
python test_web.py
```

Проверки охватывают блокировку номеров, пустой/ошибочный/верный ответ, статистику, повтор ошибок, изоляцию профилей, сохранение даты и последнего теста, все предметы, фильтр класса, защиту запросов и обработку корректного/некорректного ответа Gemini.

## Файлы

app.py — HTTP и хранение профилей; logic.py — логика тестирования; catalog.py — каталог предметов и импорт учебных материалов; gemini.py — обращение к Gemini; seed.json — перенесённые учебные материалы; templates/index.html — страницы; static/app.js — действия браузера и графики; static/style.css — оформление. Исходное настольное приложение остаётся в родительской папке.
